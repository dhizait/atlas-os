C. Low Code  vs Product as ode vs Temenos AA
---------------------------------------------

### *1. WHAT IS TEMENOS ARRANGEMENT ARCHITECTURE AA?*

*AA = "Arrangement Architecture"*  
Launched in T24 R12 / Transact. 

Core idea: *"Stop thinking Accounts. Think Arrangements."*
Old T24 Way	AA Way
1 Customer = 1 Savings Account = 1 Record	1 Customer = 1 "Arrangement" = can have 1 Loan + 3 Deposits + Overdraft + Fees all in 1 container
Product logic hard-coded in COBOL	Product = JSON/XML "Product Factory" config
Change product = code release	Change product = config + deploy
*Analogy:*  
Old: Bank vault with 100 different boxes  
AA: 1 smart container "Arrangement" that can hold any mix of products. Rules, pricing, schedules all live as data, not code.

### *2. AA vs LOW-CODE vs PRODUCT-AS-CODE*
	**Temenos AA**	**Low-Code Atlas**	**Product-as-Code Atlas**
**What it is**	A data model + rules engine inside a Core Banking System	A UI to wire existing services	A Git repo + CI/CD for services
**Level**	Data/Product Layer	Orchestration Layer	Infrastructure/App Layer
**Who builds**	Business + Product Configurators	Business PMs	Engineers
**Output**	1 "Arrangement" = Config JSON	1 "Journey" = Workflow JSON	1 "Service" = Python/Go + Terraform
**Speed**	Fast: New product in 1-2 weeks via config	Fastest: New journey in 2-3 days	Slow: New service in 2-4 weeks
**Flexibility**	High for banking products	High for UX/journeys	Highest: can code anything
**Lock-in**	100% Temenos	0%	0%
**Gov Example**	"Fertilizer Subsidy Arrangement" with rules, eligibility, payments	"Apply for Subsidy" button -> calls KYC + Payment APIs	`batch-23-subsidy-final.py` deploys the APIs
### *3. THE KEY DIFFERENCE*

Think of it as 3 layers of a cake:
LAYER 3: Low-Code Atlas      = "How user sees it"  - Button, Form, Journey
LAYER 2: Temenos AA          = "What the product is" - Arrangement, Rules, Schedule  
LAYER 1: Product-as-Code     = "How it runs" - API, DB, K8s, PS25
*Temenos AA does NOT replace Low-Code or Product-as-Code. It sits between them.*

AA replaces the need to code product logic.  
Low-Code replaces the need to code UI/journeys.  
Product-as-Code replaces the need for a vendor at all.

### *4. HOW AA WOULD MAP TO ATLAS/GRIT TODAY*

Right now in GRIT you hard-code "Subsidy" in PS10 business logic. With AA thinking:
Temenos AA Concept	Atlas Equivalent
**Arrangement**	`subsidy_arrangement` table in Postgres. Holds customer + product + status + schedule
**Product Factory**	`platform/configs/products/subsidy-v1.json`. Defines eligibility, amount, frequency
**Component**	Reuse PS05 OpenG2P, PS14 Workflow, PS16 Analytics as "components"
**AA Engine**	Rules engine in PS10. Reads JSON, calculates payments, no code deploy
So you get "configurable products" without buying Temenos.

### *5. PROS / CONS FOR ATLAS*

#### *If you copied AA pattern into Atlas*

*Pros:*
1.  *Product Speed*: Launch new grant in 1 week by editing JSON, not PS25
2.  *Audit*: Product = config in Git. Regulators love this
3.  *No Core Rewrite*: Your PS05/PS08 stay, you just add "Arrangement DB"

*Cons:*
1.  *You have to build the engine*: Temenos spent 10 years on AA. You need PS23b = "Atlas Arrangement Engine"
2.  *Complexity*: Arrangements are hard. Getting schedules, charges, penalties right is 80% of AA

#### *vs Low-Code*
AA is about "what is the product". Low-Code is about "how do I deliver the product".  
You need both. AA for backend product, Low-Code for frontend journey.

#### *vs Product-as-Code* 
Product-as-Code = "I code the subsidy logic in Python"  
AA = "I describe the subsidy logic in JSON, engine runs it"  
Product-as-Code wins for unique gov logic. AA wins for 20 similar grant types.

### *6. MY RECOMMENDATION FOR GRIT*

Don’t buy Temenos AA. *Build "Atlas AA Lite"*

Add 2 things to PS25:

1.  *PS23a: Product Factory*  
    Folder: `platform/products/`  
    `subsidy-v1.json` = eligibility, amount, disbursement rules
2.  *PS23b: Arrangement Engine*  
    Microservice that reads the JSON and executes via PS14 Temporal  
    So PS10 becomes data-driven, not code-driven

Then put *Low-Code Studio on top* so PMs can pick `subsidy-v1` + `subsidy-v2` and compose journeys.

Result: You get 70% of Temenos AA value with 10% of cost and 100% sovereignty.

Let business launch new customer journey fast	**Low-Code**
